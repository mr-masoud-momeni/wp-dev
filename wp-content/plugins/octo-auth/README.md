# Octo Auth

مستند کوتاه وضعیت فعلی افزونه احراز هویت موبایلی **Octo Auth** در شاخه `style/digikala-ui-refresh`.

## ساختار کلی

افزونه احراز هویت را بر پایه شماره موبایل و **Auth State** مدیریت می‌کند. هر جریان احراز هویت با یک Token موقت شناخته می‌شود و مقدار `flow` مشخص می‌کند کاربر در کدام مسیر قرار دارد.

Flowهای فعلی:

- `register` — ثبت‌نام
- `login` — ورود با رمز
- `reset_password` — بازیابی رمز
- ورود با OTP نیز از همان OTP flow استفاده می‌کند.

## جریان احراز هویت

### 1. بررسی شماره موبایل

`octo_check_phone()` شماره را اعتبارسنجی و کاربر را با چند Meta Key مختلف جستجو می‌کند:

- `octo_auth_phone`
- `billing_phone`
- `phone`
- `mobile`

در صورت پیدا شدن کاربر، Flow روی `login` قرار می‌گیرد؛ در غیر این صورت Flow روی `register` قرار می‌گیرد.

### 2. Auth State

برای هر جریان یک Token موقت ساخته می‌شود و اطلاعات زیر در Transient ذخیره می‌شود:

- شماره موبایل
- Flow
- زمان ایجاد
- وضعیت `verified`

مدت اعتبار Auth State برابر **۵ برابر TTL کد OTP** است.

پس از تأیید OTP، مقدار `verified` به `true` تغییر می‌کند.

## OTP

کد OTP شش رقمی است و:

- با `random_int()` تولید می‌شود.
- به مدت **۱۲۰ ثانیه** معتبر است.
- بر اساس MD5 شماره موبایل در Transient ذخیره می‌شود.
- از طریق SMS.ir ارسال می‌شود.
- پس از Verify شدن حذف می‌شود.

ارسال OTP در برابر IP Block و Rate Limit محافظت شده است.

## Rate Limit و IP Block

برای OTP محدودیت درخواست وجود دارد:

- پنجره: **۶۰ ثانیه**
- حداکثر: **۳ درخواست**

برای ورود با رمز:

- پنجره: **۵ دقیقه**
- حداکثر: **۵ تلاش**

پس از عبور از محدودیت، IP برای مدت مشخص‌شده در `OCTO_IP_BLOCK_TTL` مسدود می‌شود.

Rate Limitها با Transient نگهداری می‌شوند و پس از ورود موفق پاک می‌شوند.

## ورود با رمز

`octo_login()`:

1. Auth State را بررسی می‌کند.
2. کاربر را بر اساس شماره موبایل پیدا می‌کند.
3. رمز را با `wp_check_password()` بررسی می‌کند.
4. در صورت موفقیت، کاربر را Login می‌کند.
5. اگر شماره از Meta دیگری پیدا شده باشد، آن را در `octo_auth_phone` نیز ذخیره می‌کند.
6. Auth State را حذف می‌کند.
7. URL مقصد را برمی‌گرداند.

## ورود با OTP

بعد از Verify موفق OTP، اگر Flow برابر `login` باشد، فرانت تابع `octo_login_with_otp()` را اجرا می‌کند.

این تابع فقط موارد زیر را بررسی می‌کند:

- Token معتبر است.
- Auth State وجود دارد.
- مقدار `verified` فعال است.
- کاربر پیدا می‌شود.

سپس کاربر Login و Auth State حذف می‌شود.

## ثبت‌نام

در Flow ثبت‌نام، بعد از Verify شدن OTP:

- نام
- رمز عبور
- تأیید رمز

دریافت می‌شوند و کاربر با `wp_insert_user()` ساخته می‌شود.

شماره موبایل در Meta زیر ذخیره می‌شود:

`octo_auth_phone`

پس از ساخت کاربر، ورود خودکار انجام می‌شود.

## بازیابی رمز عبور

مسیر فعلی:

```
Password
   ↓
Forgot Password
   ↓
New Auth State
   ↓
reset_password
   ↓
OTP
   ↓
Verify
   ↓
New Password
   ↓
wp_set_password()
   ↓
Login
```

برای بازیابی رمز، یک Auth State جدید با Flow برابر `reset_password` ساخته می‌شود.

پس از Verify شدن OTP، امکان تعیین رمز جدید فراهم می‌شود.

## اعتبارسنجی رمز عبور

قوانین رمز در ثابت‌های مرکزی تعریف شده‌اند:

- حداقل ۸ کاراکتر
- حروف بزرگ
- حروف کوچک
- عدد
- کاراکتر خاص

تابع `octo_validate_password()` تمام خطاهای موجود را یکجا جمع می‌کند تا فرانت بتواند آن‌ها را به صورت لیست نمایش دهد.

## پیام‌های وضعیت فرانت

فرم OTP مشترک است و برای Flowهای مختلف دوباره استفاده می‌شود.

متن عنوان، توضیح، دکمه و Placeholder بر اساس Flow تغییر می‌کند.

برای پیام‌های معمولی از `showStatus()` و برای خطاهای چندگانه رمز از نمایش لیستی `ul/li` استفاده می‌شود.

## نکته

این مستند وضعیت فعلی پیاده‌سازی را ثبت می‌کند و قرار نیست معماری نهایی افزونه را مشخص کند. در ادامه می‌توان بخش‌هایی مثل Change Password، تنظیمات کامل سیاست رمز، محدودیت تلاش برای Verify OTP و بهبود پیام‌ها و UI را به همین ساختار اضافه کرد.
